# HaulMatch 360 PayFast Final Baseline

## One switch

Sandbox acceptance:

```env
HAULMATCH_PAYFAST_MODE=sandbox
HAULMATCH_PAYFAST_MERCHANT_ID=...
HAULMATCH_PAYFAST_MERCHANT_KEY=...
HAULMATCH_PAYFAST_PASSPHRASE=...
```

Live cutover changes only server-side values:

```env
HAULMATCH_PAYFAST_MODE=live
HAULMATCH_PAYFAST_MERCHANT_ID=LIVE_ID
HAULMATCH_PAYFAST_MERCHANT_KEY=LIVE_KEY
HAULMATCH_PAYFAST_PASSPHRASE=LIVE_PASSPHRASE
```

Restart the backend after changing environment variables. Do not edit browser JavaScript for mode changes.

## Security rules
- Checkout fields and signature are generated by FastAPI.
- Browser return never credits the wallet.
- ITN signature, merchant, reference, amount and COMPLETE status are validated.
- ITN is confirmed server-to-server with the active PayFast environment.
- Duplicate notification hashes and the payment `credited` flag prevent duplicate wallet credits.
- Secrets remain outside Git in `.env.production`.

## Acceptance before live
1. Sandbox checkout opens with the selected server-defined pack amount.
2. Valid COMPLETE ITN credits exactly once.
3. Duplicate ITN does not credit twice.
4. Invalid signature, merchant, amount and reference are rejected.
5. Cancelled checkout gives no credits.
6. Wallet and ledger reconcile.
7. Switch only environment values to live and restart.
